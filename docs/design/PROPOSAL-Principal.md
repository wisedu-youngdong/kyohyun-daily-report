# 원장 보고서 화면 재설계 제안

작성: 2026-08-02 · 대상: 원장분석 › 원장 보고서 (DirectorView + GrowthDashboard + StudentProfileModal)
시안: `Principal Dashboard.dc.html` — 1a / 1b / 1c + 학생 상세 통합안

## 0. 한 줄 요약

**시간축 3개를 1개로, 학생 상세 2벌을 1벌로.** 브랜드(네이비 #0D2D6B + 골드 #C9A227)와 페이지 위치는 그대로 두고 정보 위계만 재구성한다.

## 1. 세 안

| 안 | 성격 | 강점 | 약점 |
|---|---|---|---|
| **1a** 기간 하나, 뷰 전환 | 세그먼트 하나가 아래 전체를 지배 | 기간 혼동이 구조적으로 불가능 | 할 일이 배너 안 칩이라 처리까지 클릭이 한 번 더 |
| **1b** 할 일 우선 | 상단이 처리 가능한 목록 | 30초에 끝남. 화면 이탈 없음 | 지표가 접히면 학원 전체 흐름이 안 보임 |
| **1c** 학생 중심 단일 표 | 화면 전체가 표, 기간이 열을 바꿈 | 200명 규모에 가장 강함 | 학원 전체 상태가 상단 한 줄로 압축됨 |

**추천: 1a 구조 + 1b의 할 일 목록.** 1c의 좌측 반 레일은 학생 100명을 넘어서면 1a에 추가로 얹는다.

## 2. 핵심 문제 1 — 시간축 3개

### 결정
- **"이번 주 현황"은 기간 컨트롤과 분리해 항상 이번 주 고정.** 화면 최상단 알림 영역이며, 아래 기간을 무엇으로 바꾸든 변하지 않는다. 라벨에 "기간 설정과 무관하게 항상 이번 주"를 명시한다.
- **날짜 선택기 + 기간 토글을 하나의 세그먼트로 통합** — `오늘 / 1주 / 1개월 / 3개월`.

### 뷰 전환 규칙

| 세그먼트 | 화면에 나오는 것 |
|---|---|
| **오늘** | 날짜 네비게이션(`‹ 7월 31일 (금) ›`) → 일별 요약 4수치(수업·작성·미작성·결석) → 리포트 카드 3열 그리드 |
| **1주 / 1개월 / 3개월** | KPI 3장 → 개념 이해 평균 추이 → 학생 표(검색·반 칩·페이지네이션) |

두 뷰는 **동시에 보이지 않는다.** 이것이 이 재설계의 핵심이다 — 지금 보는 숫자가 어느 기간인지 헷갈릴 방법이 없어진다.

### 구현 메모
- 날짜 네비게이션은 "오늘" 뷰 안에서만 나타난다. 기본값은 **오늘이 아니라 가장 최근 수업이 있었던 날** (8월 2일 일요일에 열면 7월 31일 금요일이 뜬다). 이것만으로 지금의 커다란 빈 상태가 사라진다.
- 수업이 없는 날(주말·휴원)과 수업은 있었으나 리포트가 없는 날은 **다른 빈 상태 문구**를 쓴다.

## 3. 핵심 문제 2 — 학생 상세 2벌

### 결정: 하나로 통합. **풀 모달(StudentProfileModal)의 기능을 드로어 폭에 담는다.**

기능이 더 많은 쪽을 남기는 것이 맞고, 드로어 쪽에만 있던 것은 리포트 목록뿐이라 흡수가 쉽다.

| 항목 | 결정 |
|---|---|
| 표현 | **폭 420px 오버레이.** 본문을 밀지 않는다 (지금은 push라 비교 대상인 표가 찌그러진다) |
| 상단 | 학생명 + 상태 배지 + 현재 점수·변화량. 그 위에 **`‹ ›` 이전/다음 학생 이동**과 "경고 목록 1 / 3" |
| 추이 | 최근 6회 개념 이해 라인차트 (숫자 나열이던 것을 시각화) |
| 리포트 | 필터 세그먼트를 **목록 위**로 (지금은 아래에 있어 무엇을 거르는지 안 읽힌다). 각 건에 과제·개념 막대 + 진단 태그 |
| 원장 메모 | 유지. 추가 버튼 |
| 하단 | 주 버튼 = **담당 선생님에게 확인 요청**, 보조 = 링크 복사, **성장 포트폴리오는 텍스트 버튼으로 강등** (이탈 동작이 가장 강한 버튼이면 안 된다) |
| 카카오 공유 | 원장 화면에서는 뺀다 — 학부모 발송은 선생님 리포트 화면의 역할 |

### 이전/다음 이동
패널이 **표의 현재 정렬·필터 결과 배열**을 받아야 한다. 컨텍스트 라벨("경고 목록 1 / 3")로 지금 어느 집합을 훑는 중인지 표시한다.

## 4. KPI 정리

| 기존 | 변경 |
|---|---|
| 관심 필요 N명 | **유지 + 액션 버튼**("목록 보기"). 값은 경고 + 주의 합 |
| 전체 평균 | **"개념 이해 평균"으로 개명.** 과제 수행률이 빠진 값이라 기존 라벨은 오해를 부른다. 부제에 "지난 기간 70.0 · ▲3.4" |
| 총 학생 | 1a에서는 제거(표 헤더의 "42명"과 중복), 1b에서는 4번째 칸에 작게 |
| **최고 성취** | **제거.** 클릭해도 동작이 없는 순수 정보 카드다. 칭찬 용도라면 이 화면이 아니라 주간 요약·성장 포트폴리오가 맞는 자리 |
| (신규) 리포트 미작성 | 액션 있는 항목으로 승격 — "요청" 버튼 |

## 5. 0건 상태 처리

접힌 섹션이 "0건이면 클릭해도 빈 화면"인 문제:

- **0건 항목은 숨기지 않고 흐린 상태로 남긴다** — 사라지면 원장이 "확인했다"는 확신을 얻지 못한다.
- 다만 **버튼을 제거**하고 배경을 낮춘다. 클릭 자체가 불가능해야 헛클릭이 없다.
- **접근성 주의:** wrapper `opacity`로 흐리게 하지 말 것. 이미 0.75 알파인 보조 텍스트에 곱해져 0.45가 되어 AA를 벗어난다. 실제로 이번 시안에서 한 번 걸렸다. **배경색만 낮추고 텍스트 알파는 0.75를 유지**한다.

## 6. 확장성 (42명 → 200명)

시안은 42명 기준으로 그렸다.

- 학생 표에 **검색 + 반 칩 필터 + 페이지네이션**
- 기본 정렬은 **관심 필요 순** (경고 → 주의 → 안정 → 데이터 없음)
- 1c의 **좌측 반 레일**은 100명을 넘어가면 1a에도 얹는다 — 칩은 6개까지가 한계
- 상태는 색만이 아니라 항상 **텍스트 배지**를 함께 (색맹 대응 + 스캔 속도)

## 7. 숫자 일관성 — 구현 시 반드시

지금 화면의 가장 큰 신뢰 문제는 **같은 지표가 화면 안에서 다른 값으로 두 번 나오는 것**이다 (상단 "1명 미제출" vs 날짜 섹션 "4 리포트 미작성").

**시안에서는 모든 집계를 학생 배열 하나에서 파생시켰다.** 알림 칩, 일별 요약, KPI, 할 일 목록, 좌측 레일, 상단 스트립, 반 칩 카운트가 전부 같은 소스를 읽는다. 구현에서도 동일하게:

```
경고/주의/안정/데이터없음 수  ← students.filter(status)
미작성 건수 + 이름            ← students.filter(today === '미작성')
작성률                        ← 작성 / (전체 - 결석)
개념 이해 평균                ← score !== null 인 학생 평균
이번 주 할 일 총계            ← 미작성 + 미답변 + 참여도조정
```

숫자를 화면에 직접 적는 코드가 하나라도 남으면 같은 문제가 재발한다.

## 9. 차트 규칙

라이브러리 없이 순수 SVG.

- **격자선 y좌표를 절대 하드코딩하지 말 것.** 폴리라인과 같은 매핑 함수에서 뽑는다. 이번 시안에서 실제로 어긋났고, 69점이 "75" 선 위에 그려졌다.
- **도메인은 0–100이 아니라 데이터 범위에 맞춘다.** 학원 평균은 66–76 구간에 몰려 있어 0–100으로 그리면 3.4점 개선이 4px 차이로 보이지 않는다. 시안은 **50–100**을 쓴다.
- 지난 기간 비교선은 점선 `#9CB0D0`, 이번 기간은 실선 네이비 2.5px

## 10. 결정 필요

1. **경고/주의 임계값** — 코드상 어디에 있고 원장이 조정 가능한지. 조정 가능하면 설정 진입점이 필요하다
2. **"관심 필요"의 정의** — 경고 + 주의 합인지, 경고만인지. 시안은 합으로 그렸다
3. **변화량 기준** — ▼10이 직전 수업 대비인지 기간 평균 대비인지. 라벨에 명시해야 한다
4. **미제출 / 리포트 미작성** — 두 개념이 실제로 다른지. 같다면 하나의 용어로 통일한다
5. **이전/다음 이동의 범위** — 현재 필터 결과 전체인지, 상태 그룹 안인지. 시안은 "경고 목록 1 / 3"으로 그룹 안을 가정했다
6. **주차 계산 버그** — "8월 0주차". 수정 난이도만 알려 달라
7. **서우영 / 서우성** — 실제로 다른 학생인지, 데이터 오류인지
8. **선생님 여러 명일 때** — 원장 보고서에 선생님별 필터·집계가 필요한지

## 11. 디자인 시스템 함정 (실제로 겪음)

시안은 DS 번들을 쓰지만 실제 구현은 인라인 스타일 + 자체 토큰이므로 참고용. 아이콘을 가져다 쓸 경우:

1. **아이콘은 24×24 고정.** 루트가 `width: fit-content`인데 글리프가 전부 `position:absolute`라 루트 폭이 0으로 붕괴한다. 래퍼를 `24×24 + justify-content:flex-start; align-items:flex-start`로 두면 정확히 겹친다
2. **아이콘 색은 부모 상속이 안 된다** — 루트에 인라인 `color`가 박혀 있다. 색은 컴포넌트 자신에게 넘겨야 한다
3. **`IconNormalTrash3`, `IconNormalArrowRight`는 쓰지 말 것** — 내부에 Figma 레이아웃 가이드(`_Ratio`)가 있어 점선 박스와 "Ratio" 텍스트가 렌더된다. 검증된 것: `IconNormalChevronLeft/Right/Up/Down`, `IconNormalSearch`, `IconNormalTrash`
4. **`ButtonButton`은 파괴적 variant가 없다** — 링을 `box-shadow inset`으로 그리고 라벨 `<span>`에 인라인 색을 하드코딩하므로 어떤 prop으로도 빨갛게 못 만든다. 자체 버튼으로 그린다
